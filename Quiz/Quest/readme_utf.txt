TemplateSource - источник, генерирующий по шаблону

FileSource - производный от SetSource: в контейнер загружаются данные из файла
FileTupleSource - производный от TupleSetSource: в контейнер загружаются данные из файла

TemplateSource инициализируется скриптом
в конструкторе задается имя файла со скриптом и рабочий каталог (разделитель // необязателен)
ко всем упоминаемым в скрипте именам файлов добавляется рабочий каталог

Генерация по щаблону выполняется как последовательность текстовых подстановок.

разбор скрипта и построение объекта класса TemplateSource осуществляется классом Builder
на данный момент осуществляется построчный разбор

пустые строки, строки белых символов и строки-комментарии игнорирутся в любой части скрипта
комментарий - строка, начинающаяся с //

формат скрипта:
<script>={<sample-section>|<declarations-section>|<template-section>|<restrictions-section>}
Скрипт состоит из четырех типов секций, которые могут повторяться и располагаться в любой последовательности:
секция примера
секция объявлений
секция шаблона
секция ограничений

Для текущей версии Builder:
   секции могут располагаться в скрипте в любой последовательности
   секции могут быть пропущены
   все секции, кроме секции шаблона, могут повторяться

Секция примера:
  предполагается, что содержит пример текста, сгенерированного по шаблону
  содержимое игнорируется
<sample-section>=
    "<sample>"
    {<lines>}
    "<\sample>"

Секция ограничений:
  предполагается, что будет содержать ограничения для генерации по шаблону (например, n!=m)
  на данный момент содержимое игнорируется
<restrictions-section>=
    "<restrictions>"
    {<lines>}
    "<\restrictions>"

Секция шаблона:
<template-section>=
    "<template>"
    {<lines>}
    "<\template>"

Строки секции шаблона подвергаются операции trim и конкатенируются в один результирующий шаблон-строку.
Разделители строк при конкатенации НЕ добавляются.
В строках шаблона и строках секции объявлений поддерживаются ключевые слова ENDL, TAB, SPACE,
которые, записанные в фигурных скобках, задают соответствующие белые символы.
Например, Строка.{ENDL}А этот текст будет выведен уже на новой строке.

Секция деклараций:
<declarations-section>=
    "<declarations>"
    {<declaration>}
    "<\declarations>"

Состоит из отдельных строк, на которых декларируются константы или переменные
<declaration>=<const-declaration> | <var-declaration>
Константы имеют сементику именованных последовательностей символов.
Переменные задают контейнеры значений.

<const-declaration>="const" <spaces+> <id> <spaces> "=" <spaces> <definition>
<id>=<any sequence of symbols>
<definition>=<any sequence of symbols>
Ограничений на имя константы нет.
Количество пропусков - произвольное, но хотя бы один пропуск после const должен быть.
(Символ, следующий за const игнорируется.)
Определение константы подвергается операции trim, после чего выполняется подстановка значений ключевых слов.
Допустимо использовать в определении константы переменные
(их разименование произойдет только на этапе генерации по шаблону).

<var-declaration>=<id> <spaces> "=" <spaces> <var-definition>
Определение переменной также подвергается операции trim, после чего выполняется подстановка значений ключевых слов.

<var-definition>= <reference>|<simple-list>|<braced-list>|<bracket-list>
Определение переменной может использовать определение другой переменной, простой список значений или списком более сложных елементов.

<reference>= "#"<id>
Если определение переменной начинается с символа #, то дальнейшие символы интерпретируются как имя,
а строка
var1=#var2
интерпретируется как "использовать в качестве определения переменной var1 определение переменной var2".
В результате имена var1 и var2 обозначают контейнеры с одним и тем же множеством значений.
Различие в том, что получаемые из контейнеров значения независимы друг от друга.

<simple-list>={<value>";"}<value>
<value>=<any sequence of symbols (except ;)>
Определение переменной может быть простым списком, в котором отдельные значения разделены между собой символом ;.
Допускаются пустые строки в качестве значений. Значения могут повторяться. Символ ; в значениях содержаться не может.


<braced-list>={<part>}
<part>="{"(<value> | <file-source> | <interval> )"}"
Каждая часть определения записывается в фигурных скобках.
Она может быть
  одиночным значением,
  загружаться из файла,
  интервалом значений базовых типов.

<value>=<any sequence of symbols (except })>
Одиночное значение может быть любой последовательностью символов, не содержащей символ }.
Операция trim не применяется.

<file-source>= "<file>" <spaces+> <filename>|"<file:" <spaces> <int> <spaces+> ">" <spaces+> <filename>
<filename> = """ <name> """ | <name>
например,
<file> "1.txt"
<file> 1.txt
После <file> в кавычках или без указывается имя файла.
Операция trim применяется к <filename>, поэтому в случае наличия белых символов в начале или конце имени файла
использование кавычек необходимо.
Данный элемент добавляет в контейнер информацию из файла (к имени файла добавляется рабочий каталог).
При загрузке пустые строки игнорируются, применяется trim.
Режим загрузки - элемент располагается на 1 строке.

<file:3> "1.txt"
Режим загрузки: элемент контейнера получается в результате конкатенации 3 непустых строк файла

<interval>=<char-interval> |<int-interval> | <double-interval>
На данный момент поддерживаются интервалы символов, целых и действительных.

<char-interval>="<char>" <spaces> <from> <spaces+> <to>
<int-interval>="<int>" <spaces> <from> <spaces+> <to>
<double-interval>="<double>" <spaces> <from> <spaces+> <to> <spaces+> <step> <spaces+> <precision>

В контейнер записываются строки, содержащие представления значений указанных типов от from до to включительно.
Действительные записываются в формате с фиксированной точкой и указанным количеством десятичных знаков.
Для интегральных типов используется шаг 1. Для действительных используется значение step.


<bracket-list>="["<arity> <spaces+> <filename>"]"
<arity>=<int>
Содержимое файла загружается в контейнер векторов, где каждый вектор имеет размер <arity>.
Пустые строки игнорируются.

Некоторые особенности шаблона и генерации по шаблону.
Генерация по шаблону начинается с того, что для каждой переменной добываются текущие значения и
запоминаются в таблице, индексированной именами переменных.
Далее проходом по таблице каждое вхождение текста #var# заменяется на текущее значение переменной var.
Для каждого вхождения (начиная первым и заканчивая последним) выполняется текстовая подстановка.
Если в результате подстановки появляются новые вхождения, то они не обрабатываются.
При этом возможна в некотором смысле рекурсия.
Пусть текущим значением переменной a является строка x#b#y, а значением b - строка $$$.
Тогда из шаблона 12#a#354 получится строка 12x$$$y354.
12#a#354 -> 12x#b#y354 -> 12x$$$y354

Если в результате подстановки появляются упоминания переменных, для которых подстановки значений еще не выполнялись,
то они будут выполнены на последующих этапах преобразования. Переменные обрабатываются в лексикографическом порядке имен.
Таким образом можно, например, варьировать шаблоны для генерации, не создавая дополнительных смешивающих фабрик.
Например.
<declarations>
a={#x1##x2#0#x4##x5##x6##x7#1}{#x1#1#x3##x4##x5##x6#0#x8#}
x1=0;1
x2=#x1
x3=#x1
x4=#x1
x5=#x1
x6=#x1
x7=#x1
x8=#x1

<\declarations>

При необходимости использовать в шаблоне различные элементы одного контейнера можно использовать конструкцию
#var new#
Все такие конструкции обрабатываются после обработки конструкций вида #var#. В случае #var# берется одно и то же
значение для всех вхождений #var#. В случае #var new# для каждого вхождения генерируется новое значение переменной,
которое и подставляется.

Для контейнера векторов #var[k]# задает k-ый элемент текущего вектора (нумерация с 0).
Конструкция #var new# в этом случае не поддерживается (пока).

Скрипт для генерации документа

Скрипт интерпретируется построчно.
Пустые строки и строки-комментарии игнорируются.
К строка применяется операция trim.

Содержит
  секцию описания параметров документа,
  секцию описания варианта и
  последовательность секций с описаниями отдельных элементов варианта.

Именно в указанной последовательности.

Секция описания параметров документа
<document>
содержание секции
<\document>

Может содержать подсекции:

<header> задает текст, добавляемый в начало всего документа с вариантами
<footer> задает текст, добавляемый в конец всего документа с вариантами
<onNextVariant> задает текст, добавляемый в конец варианта, который не завершает страницу
<onNextPage> задает текст, добавляемый в конец варианта, который должен завершать страницу
<from> номер первого варианта (по умолчанию 1)
<to> номер последнего варианта (должен быть не меньше первого) (по умолчанию 1)
<onPage> количество вариантов на страницу (по умолчанию 1)

Секция описания варианта
<variant>
содержание секции
<\variant>

Может содержать подсекции:
<before> текст, добавляемый в начало каждого варианта перед вопросами
(номер варианта подставляется вместо #No#)
<after> текст, добавляемый в конец каждого варианта после вопросов

Секция описания элементов варианта
<item>
содержание секции
<\item>

Может содержать подсекции:
<delim> задает текст, добавляемый после вопроса
<fabric> задает фабрику, используемую для получения впороса
или инструкцию включения файла с секцией описания фабрики, например
include fabric_5.txt
файл рассматривается как файл в рабочем каталоге

Секция описания фабрики:
<fabric>
   тип фабрики
   подсекции (в зависимости от типа возможны варианты)
<\fabric>

Можно задавать фабрики таких типов
collate
file answer
template answer
check
check auto

Описание фабрики типа collate:
 содержит две подсекции с описаниями фабрик (возможно использование include)
может содержать подсекции
<n1> количество элементов из первой фабрики (по умолчанию 0)
<n2> количество элементов из второй фабрики (по умолчанию 0)
Нулевые количества приведут к тому, что в процессе слияния будут использованы размеры фабрик.

Описание фабрики типа file answer может содержать подсекции:
 <fname> - имя файла из рабочего каталога с содержимым для источника фабрики, обязательный
 <num> - количество строк, которые занимает один вопрос (по умолчанию 1)
 <before> - текст, добавляемый перед каждым вопросом
 <after> - текст, добавляемый после каждого вопроса

Описание фабрики типа template answer может содержать подсекции:
 <fname> - имя файла из рабочего каталога со скриптом, обязательный
 <before> - текст, добавляемый перед каждым вопросом
 <after> - текст, добавляемый после каждого вопроса

Описание фабрики типа check может содержать подсекции:
  <fname> - имя файла из рабочего каталога с содержимым для источника фабрики, обязательный;
  <ncase> - количество пунктов в вопросе, обязательный
  <AfterForEachInFile> - наличие индивидуальной концовки вопроса в файле (если есть, то true)
  <before> - текст, добавляемый перед каждым вопросом
  <after> - текст, добавляемый после каждого вопроса
  <mode> - режим вывода пунктов (TabBetween, TwoOnLine, SpaceBetween, OneOnLine - по умолчанию)
  <delimBeforeCases> - текст-разделитель, выводимый перед первым пунктом вопроса

Описание фабрики типа check auto может содержать подсекции:
  <good> - имя файла c правильными варианатми ответов, обязательный;
  <bad> - имя файла с неправильными вариантами ответов, обязательный;
  оба файла берутся из рабочего каталога
  <ncase> - количество пунктов в вопросе, обязательный
  <nGood> - количество пунктов с правильными ответами, обязательный
  <before> - текст, добавляемый перед каждым вопросом
  <after> - текст, добавляемый после каждого вопроса
  <mode> - режим вывода пунктов (TabBetween, TwoOnLine, SpaceBetween, OneOnLine - по умолчанию)
